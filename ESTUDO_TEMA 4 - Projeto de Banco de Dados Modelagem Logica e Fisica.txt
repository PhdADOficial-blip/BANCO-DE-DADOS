1.1 MODELAGEM LOGICA E FISICA - CHAVE PRIMARIA 

    TODA TABELA DO MODELO RELACIONAL TEM QUE TER UMA CHAVE PRIMARIA 

    CHAVE PRIMARIA - GERADA ATRAVES DE UM ATRIBUTO IDENTIFICADOR DE UMA TABELA (RELAÇÃO)

    DEFINIÇÃO: ATRIBUTO DA RELAÇÃO, CUJA OS VALORES MANTEM UMA RELAÇÃO BIUNIVOCA(1,1) COM A TUPLA

        CARACTERISTICAS: 
            INTEGRIDADE DA ENTIDADE 
                O VALOR NÃO PODE SER VAZIO (NULL), POIS ELA REPRESENTA UMA ENTIDADE 

            INTEGRIDADE DE CHAVE PRIMARIA 
                VALOR ÚNICO = BIUNIVOCA
                UNICA LINHA 
        RESUMO CARACTERISTICA:
         Unicidade: 
         Não Nulidade (NOT NULL): 
         Imutabilidade (Estabilidade): 
         Minimalidade:

        EXISTE DOIS TIPOS DE - CHAVE  PRIMARIA -

            SIMPLES   = ID        

            COMPOSTA  = RESPONSAVEL + ID  (DOIS ATRIBUTOS PARA FORMA UMA CHAVE PRIMARIA)

            CANDIDATA = PREREQUISITO ( VALOR UNICO POR TUPLAS - SIMPLES OU COMPOSTA )

        ORIGEM DOS DADOS 
            NATURAL = JA EXISTE NO MUNDO REAL EX, CPF, CNPJ, PLAVA_VEICULO
            
            ARTIFICIAL = GERADA AUTOMATICAMENTE OU SEGUENCIAL

                     1     |               1

            Como ler essa notação (Regras padrão):

            1. NOME DA TABELA: Escrito em letras MAIÚSCULAS fora dos parênteses (ex: CLIENTE).
            2. Atributos (Colunas): Escritos dentro dos parênteses, separados por vírgula.
            3. Chave Primária (PK): Fica sublinhada (ou marcada com PK ao lado, quando a plataforma não permite sublinhar).
                • Nota: Na tabela ITEM_PEDIDO, ID_Pedido e ID_Produto estão ambos sublinhados porque formam uma Chave Primária Composta.
            4. Chave Estrangeira (FK): Fica em itálico (ou tracejada, ou marcada com FK ao lado). Logo abaixo da tabela, indica-se qual tabela e coluna ela referencia.

2.0 MODELAGEM LOGICA E FISICA - NORMALIZAÇÃO
    
    OBJETIVO:
        EVITAR REDUNDANCIA 
        PROCESSO PARA MELHORA A ESTRUTURA DA TABELA - EVITAR ANOMALIA
        MELHORAR A CONSISTÊNCIA E A INTEGRIDADE DOS DADOS 
    PRINCIPIOS NORTEADOR
        1- ARMAZENA UMA UNICA VEZ 
        2- ECONOMIA DE ESPAÇO 
      IDEIA = VAMOS ARMAZENAR VARIOS DADOS UMA UNICA VEZ E ESPALHAR EM TABELAS SEPARADAS 
     
  REPRESENTAÇÃO FORMA NORMAIS  
    
    RELAÇÃO NÃO-NORMALIZADO         | ESTUDAR 
            1FN                     ^ ESTUDAR 1
               2FN                  | ESTUDAR 2
                  3FN               ^ ESTUDAR E 3
                     BCNF           | EFEITOS PRATICOS NÃO MUITO IMPORTANTE 
                         4FN        ^ EFEITOS PRATICOS NÃO MUITO IMPORTANTE 
                            5FN     | EFEITOS PRATICOS NÃO MUITO IMPORTANTE 
    OBS: SE ESTA NA QUINTA ESTA EM TODAS FORMAS.

    EXEMPLO PRATICO:

         TABELA PEDIDO (DADOS TUDO MISTURADO)          
            CASOS ANOMALIA 
                1- ANOMALIA DE INCLUSÃO 
                        NÃO POSSO FAZER UM CADASTRO DE UM CLIENTE SE ELE NÃO COMPRA 
                2- ANOMALIA DE EXCLUSÃO 
                    SE APAGA O CLIENTE APAGA TODO O HISTORICO DE COMPRA 
                3- ANOMALIA DE ALTERAÇÃO 
                    SE UM PRODUTO MUDA DE PREÇO, TEMOS QUE PASSAR POR TODOS OS DADOS 

    EXPLICAÇÃO DO PRPCESSO:
    1- UMA FORMA NORMAL É UM CONJUTO DE REGRAS QUE UMA TABELA DEBVE SEGUIR 
    2- O PROCESSO DE NORMALIZAÇÃO VAI EVITAR ANOMALIAS 
    3- E CONVERTE PROGRESSIVAMENTE UMA TABELA EM TABELAS DE GRAU E CARDINALIDADE MENORES ATE QUE POUCO OU NENHUMA REDUNCÃNCIA DE DADOS EXISTA
    EXEMPLO:  1F PARA -> 2F PARA -> 3FN ...GRADUAL 

    4- ELIMINAR DEPENDENCIAS FUNCIONAIS (CONCEITO A SER ESTUDADO)
    5-CADA PASSO COLOCA A RELAÇÃO EM UMA DAS FORMAS NORMAIS 
    
    6- SE BEM SUCEDIDIO 
        RESULTADO:
            1- ESPAÇO DE ARMAZENAMENTO DIMINUI 
            2- ATUALIZA A TABELA COM EFICIENCIA 
            
2.1 MODELAGEM LOGICA E FISICA - PRIMERIA FORMA NORMAL (1FN)

    OBJETIVO:  PALAVRA CHAVE (ATOMICIDADE)
      CASO PROBLEMA:
        AS TABELAS NÃO NORMALIZADAS CONTEM:
         (ATRIBUTOS NÃO ATÔMICOS/TABELAS EMBUTIDAS) =  ATRIBUTOS MULTIVALORADOS, CELULAS COM LISTAS E MATRIZES 

         (GRUPOS REPETIDOS)                         =  COLUNAS REPETIDAS COM O MESMO NOME IDENTIFICADOR 
        
      REGRAS PARA ADICIONAR PARA 1 FROMA NORMAL 
          TODOS OS ATRIBUTOS ATÔMICOS, (CONCEITUAL) SIMPLES E MONOVALORADA   = DADO UNICO DENTRO DA CELULA 
          COLUNAS UNICAS ATOMICAS

          -SINGULARIDADE DAS LINHAS: LINHA EXCLUSIVA, COM IDENTIFICADOR DISTINTO (CHAVE PRIMARIA QUE GARANTE NÃO DUPLICIDADE)
          -ORDENS DE ARMAZENAMETNO E RECUPERAÇÃO NÃO IMPORTA NO DESIGN BD
          -NO DUPLICATED COLUMNS: SEM COLUNAS REPETIDAS COM MESMO DADO 
          -ATOMICIDADE: CADA COLUNA DEVE TER VALORES INDIVISIVEIS (SEM LISTA ,MATRIZES)

      NA PRATICA 
          PARA CADA TABELA EMBUTIDA 
            CRIASE UMA TABELA COM AS REGRAS NA 1FN QUE CONTEM: 
              1- CHAVES PRIMARIAS DE CADA TABELA EXTERNA A TABELA EMBUTIDA  
                Etapa 1: Identificar valores não atômicos e grupos de repetição
              2- OS ATRIBUTOS DA PROPRIA TABELA EMBUTIDA 
                Etapa 2: Separe os valores em novas linhas
              3- DEFINIMOS AS CHAVES PRIMARIAS DAS TABELAS USANDO A REGRA DA 1FN   
                Etapa 3: Garantir a consistência


 EXEMPLO PRATICO 
   CASO 1 TABELAS DE PEDIDOS DE CLIENTES COM DUAS COLUNAS 
     [PRODUTO1]  - [PRODUTO2]
       APPLES       BANANNAS
    
      SOLUÇÃO: DIVIDA AS LINHAS PARA QUE CADA LINHA CONTEM DADOS UNICOS DE CADA COLUNA

   CASO 2 TABELA NOTA ALUNO 
     [ALUNO]  -  [NOTA]
      JOÃO        A,B,C 
   
       SOLUÇÃO: CRIE LINHAS SEPARADAS PARA CADA NOTA 
   
   CASO 3 

2.2 MODELAGEM LOGICA E FISICA - SEGUNDA  FORMA NORMAL (2FN)

    OBJETIVO:  PALAVRA CHAVE (DEPENDENCIAS)
      A segunda forma normal é uma etapa de normalização do banco de dados que se concentra na eliminação de dependências parciais
    
    DEPENDENCIA FUNCIONAL 
        UMA COLUNA SEMPRE VAI DA O MEMSO VALOR NA OUTRA 
    
    REGRAS PARA ADICIONAR PARA 2 FROMA NORMAL 
        1- ESTA NA 1FN: ATOMICIDADE:       CELULA COM UNICO VALOR 
                        LINHAS EXCLUSIVAS  CADA TABELA DEVE TER CHAVE PRIMARIA CLARA 
        2- ELIMINAR DEPENDÊNCIAS PARCIAIS 
            1- IDENTIFIQUE TODAS AS CHAVES CANDIDATAS -> CONJUNTO MINIMO DE ATRIBUTO QUE IDENTIFICA A LINHA (CHAVES CANDIDATAS)
            2- DETERMINE AS DEPENDÊNCIAS FUNCIONAIS -> IDENTIFICAR COLUNAS NÃO PRIME (PARCIAL)
            3- ELIMINAR DEPENDÊNCIAS PARCIAIS 
               - MOVER ATRIBUTOS PARA NOVA TABELA 
                - CERTIFIQUE QUE ESSA TABELA TENHA CHAVE PRIMARIO DE ONDE ELA SAIU 
                - CERTIFIQUE QUE TENHA CHAVE PRIMARIO EXCLUSIVA (GARANTE QUE O DADO NÃO SE REPITA)
            4- REPITA ATE QUE NÃO HAJA MAIS DEPENDENCIAS 

    NA PRATICA:
 
    
        - CRIE TABELAS PARA COM OS ID 
        - CRIE TABELAS ONDE SEUS ID(CHAVE PRIMARIA) REPRESENTA FIELMENTE AS DEMAIS COLUNAS
        - AS TABELAS QUE SAIRAM DE OUTRAS TABELAS LEVAM SUAS CHAVES PRIMARIAS (VIRAM CHAVES ESTRANGEIRAS)
        - E CERTIFIQUE DENTRE AS COLUNAS QUE REPRESETAM AQUELA TABELA UMA COLUNA CHAVE ESCLUSIVA (DADO QUE NÃO SE REPETE)
    
  Exemplo 1: Tabela de inscrição no curso
    [ID do aluno]	[ID do curso]	[Nome do curso]	[Nome do instrutor]

  VAI SE TORNAR DUAS TABELAS 

    Tabela de inscrição no curso
    [ID do aluno]	[ID do curso]

    Tabela de detalhes do curso
    [ID do curso]	[Nome do curso]	[Nome do instrutor]

3.1 MODELAGEM LOGICA E FISICA - MAPEAMENTO DE RELACIONAMENTO
    OBJETIVO:
      MAPEAMENTO DE RELACIONAMENTOS 
      MAPEADO ATRAVES DAS CHAVES ESTRANGEIRA (CHAVE PRIMARIA DE OUTRA TABELA)

    REGRAS:
        TER CUIDADO DA CARDINALIDADE 
        (_,M)--<>--(_,N) 
        1-CRIA UMA TABELA PARA O RELACIONAMENTO 
        2-RECEBE A CHAVE PRIMARIA DOS DOIS 
        3-RECEBE SEUS ATRIBUTOS 

        (_,1)--<>--(_,N)  
        1-CHAVE LADO 1 PARA ->N (COMO CHAVE ESTRANGEIRA)
        2-E OS ATRIBUTOS DO RELACIONAMENTO

        (_,1)--<>--(_,1)  
        1-PODE ESCOLHE AMBAS OS LADOS PARA JOGAR CHAVE(PK)
        2-E OS ATRIBUTOS DO RELACIONAMENTO

        AUTO RELACIONAMENTO 
        (_,1)--<>--(_,1) 
        1-LEVA A CHAVE MAIS O PAPEL 

        (_,1)--<>--(_,N) 
        1-LEVA CHAVE LADO 1 PARA ->N 
        2-LEVA O PAPEL

        (_,M)--<>--(_,N)
        1-CRIA UMA TABELA PARA O RELACIONAMENTO 
        2-ADICONA SEUS PAPEIS
        3-ADICIONE O ATRIBUTO DO RELACIONAMENTO  

        AGREGAÇÃO ASSOCIATIVA/AGREGAÇÃO
        (_,M)--<>--(_,N) 
        1-CRIA UMA TABELA 

        (_,1)--<>--(_,N)
        1-CHAVE 1 PARA N 

        (_,1)--<>--(_,1) 
        1-ESCOLHE O LADO QUE JOGA A CHAVE 

        RELACIONAMENTO TERNARIO 
        1- CRIA UMA TABELA PARA OS 3 
        1- CRIA UMA TABELA PARA O RELACIONAMENTO COM CHAVE COMPOSTA

3.3 MODELAGEM LOGICA E FISICA - MAPEAMENTO DE ESPECIALIZAÇÃO/GENERALIZAÇÃO

        CRIA TODOS OS FILHOS COM OS DADOS DO PAI 
   1 - PRESERVAÇÃO DA GENERALIZAÇÃO
        CRIA O PAI COM TODOS OS FILLHOS

    2 OPÇÃO: 
    CRIA SOMENTE OS FILHOS QUE ERDAM CHAVE PRIMARIA DO PAI 

    3 OPÇÃO: 
    CRIA SO O PAI - COM TODOS OS ATRIBUTOS DOS FILHOS

4.0 MODELAGEM LOGICA E FISICA - CONSULTA E TRANSAÇÕES EM BANCO DE DADOS

    EXECUÇÃO DE COMANDOS 

        TRANSAÇÕES  
            COMANDO PARA MODIFICAR 
                ex: UPDATE (TROCA DADO ANTIGO PARA NOVO)

                ROLLBACK -> RETORNA TRANSAÇÕES ABTIGA (DEFAZ O QUE FEZ )
                COMMIT -> SALVAR

         PROPRIEDADE DAS TRANSAÇÕES = ACID
            ATOMICIDADE - O FAZ INTEIRA O NÃO FAZ NADA 
            CONSISTÊNCIA - LEVAR DE UNS ESTADO PARA OUTRO CONSISTENTE 
            ISOLAMETNO - UMA NÃO INTERFERE COM A OUTRA 
            DURABULIDADE -DADO VAI ESTAR LA 

    COMANDO PARA ATOMICIDADE 

        BEGIN TRANSACTION
        UPDATE CONTA 
        SET SALDO = SALDO -200
        WHERE NRCC= 1000
        UPDADE CONTA
        SET SALDO = SALDO + 200
        WHERE NRCC = 1002

4.4 MODELAGEM LOGICA E FISICA - Desnormalizar para ganhar desempenho

    CONTESTUALIZAÇÃO 
        3FN - > REDUNCANCIA MINNIMIZADOS (EM GERAL TEM UMA TABELA OARA CADA OBJETO MODELADO)

        SE QUISERMOS DESEMPENHO O PROFESSOR FALOU QUE TEMOS QUE SACRIFICAR AS VANTAGENS DE UM MODELO NORMALIZADO

        PROCESSO CHAMADO DE DESNORMALIZAÇÃO 
        ---------------------------------------------------
        PORQUE? 
        ---------------------------------------------------
        EX: 
        BIBLIOTECA 
        TABELA AUTOR 
        ID_AUTOR, NOME 

        TABELA LIVROS 
        ID_LIVRO, TITULO, ID_AUTOR

        TABELA CATEGORIA 
        ID_CATEGORIA,NOME 

        TABELA LIVRO_CATEGORIA
        ID_LIVRO, ID_CATEGORIA


                TABELA DESNORMALIZADA
                ID_LIVRO, TITULO, NOME AUTOR, CATEGORIA

        NA PRATICA
        A FUNÇÃO DE JUNÇÃO E UMA OPERAÇÃO CUSTOSA LEVA MUITO TEMPO E CUSTO DE PORCESSAMENTO 

        DE FORMA NORMALIZADA 

        --CONSULTA NA ESTRUTURA NORMALIZADA
        SELECT l.TITULO, A.NOME, C.NOME
        FROM LIVROS l
        JOIN AUTORES A ON L.ID_AUTOR = A.ID_AUTOR
        JOIN LIVROS_CATEGORIAS LC ON L.ID_LIVRO = LC.ID_LIVRO
        JOIN CATEGORIAS C ON LC.ID_CATEGORIA = C.ID_CATEGORIA;

        --CONSULTA NA ESTRUTURA DESNORMALIZADA 
        SELECT TITULO, NOME_AUTOR, CATEGORIAS
        FROM LIVROS_DESNORMALIZADOS;

            VANTAGEM 
            1- DESNORMALIZAR GANHA TEMPO NA CONSULTA 
            2- DESEMPENHO DE LEITURA, MENOR CARGA DO BANCO 

            DESVANTAGEM 
            1- REDUNCANCIA = NOMES REPETIDOS(HA POSSIBILIDADE DE ERRA A OINSERIR UM DADO )
            2- MANUTENÇÃO COMPLEXA = ATUALIZAR SIGNIFICADA VERIFICAR MUITOS DADOS REPETIDOS 
            3- FLEXIBILIDADE REDUZIDA = COMPLEXIDADE
